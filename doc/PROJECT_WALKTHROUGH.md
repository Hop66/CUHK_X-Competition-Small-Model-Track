# 第 0 部分:名词快查(纯小白先看这个,别的先别管)

> 本文假设你**懂一点点机器学习**(知道什么是训练、模型、准确率)。下面这些词在全文反复出现但不展开解释,**哪个眼生就回来对这张表**。完整版 60+ 个名词在配套文档 `doc/METHODOLOGY_TEACHING.md` 的"前置知识与名词速查表"。

# 第一部分:一分钟建立全局认知

## 1.1 这个项目是干什么的

**一句话**:在"没有 RGB 彩色摄像头、模型不能超过 100MB"的极简条件下,利用深度、红外、热成像、3D 骨架、IMU、毫米波雷达 6 种传感器,判断一个人在 40 类日常动作里正在做哪一个(喝水、刷牙、走路、看电视……),并且要能泛化到**从未见过的 12 个陌生人**。

这是 **CUHK-X 数据集的小模型赛道(Small Model Track)**,一个 Kaggle 风格的竞赛项目。

## 1.2 任务三要素

| 要素 | 内容 |
|------|------|
| **输入** | 一个测试 clip,包含 6 个模态子文件夹:`Thermal`、`Depth_Color`、`IR`、`Skeleton`、`IMU`、`Radar` |
| **输出** | 一个 CSV:`path,prediction`(`small_model_track_test/SM_test_0001/`, `23`),即每个 clip 一个 0~39 的类别号 |
| **三项硬约束** | ① **RGB-Free**:测试集不提供 RGB 彩色图(隐私场景,只能靠深度/红外/热像等);② **跨被试(cross-subject)**:测试 405 个 clip 来自**训练时从未见过的 12 个人**,不能用"记住人长相"作弊;③ **模型 ≤ 100MB**:提交时加载的全部权重打包后 < 100MB |

## 1.3 数据全景(实测定死,不是猜的)

| 项目 | 事实 |
|------|------|
| 训练规模 | 2891 个 clip / 40 类 / **18 个被试**(user1-9 + user16-24) |
| 测试规模 | 405 个 clip,全 6 模态齐全 |
| 类别分布 | 长尾严重:Walk 324 个 vs Watch_TV 11 个,**长尾比 29.5** |
| 缺失率 | Thermal 0%、Depth/IR 3.6%、IMU 4.5%、Radar 4.2% |

**关键物理事实(整个项目的设计起点)**——传感器硬件拓扑决定了模态能不能"对齐":

```
Goermicro Vzense NYX 650(同一台相机,同时输出)
   ├── Depth_Color  伪彩色深度图(jet 色带,不是自然 RGB!) ~10fps
   ├── IR           主动红外灰度(人体剪影最清晰)      ~10fps
   └── Skeleton     MMPose 在 RGB 上提取的 17 关节 3D 坐标(隐藏的,与上面同坐标系)

Hikvision TB4117(独立热成像相机,独立视场/帧率)
   └── Thermal      ironbow 伪彩色热力图 320×240 ~25fps

5 × WitMotion IMU(手腕×2 + 脚踝×2 + 腰) ~100Hz
1 × TI IWR6843ISK mmWave 雷达(稀疏点云 + 多普勒速度) 20fps
```

**结论 → 设计原则**:
- **Depth + IR + Skeleton 同相机帧号天然对齐 → 可以"早融合"**(拼通道)。
- **Thermal 是独立相机 → 只能单独建模,再做"晚融合"**。
- **Skeleton 是 3D 米制坐标(不是像素)→ 不能拿去裁图像,只能独立建模**。

## 1.4 最终技术栈怎么搭起来的(先看全景,细节后面展开)

```
                 ┌─ Depth(3ch) + IR(1ch) 按帧号拼成 4ch 视频 ─┐
                 │  YOLO11n 在 IR 上检测人 → 全程一个固定窗口裁剪  │
                 │  R2Plus1D-34(IG-65M 预训练, stem 改成 4ch 输入)  │→ 主模型 0.71
                 │  全量 18 被试训练 + 2 个 seed 集成 + flip TTA        │
                 └───────────────────────────────────────────────────┘
                                                                        \
                 ┌─ Thermal(3ch 伪彩色) 独立视频模型  ────────────┐        \  决策级
                 │  R2Plus1D-34(IG-65M, Kinetics 归一化)             │→ 副模型 0.63    →  prob 平均 = 0.73 LB
                 └─────────────────────────────────────────────────┘        /
                                                                          /
                 ┌─ 量化打包:每折/每模型独立 int5 量化(bit-packing)──┐ /
                 │  main 40MB + thermal 40MB = 80MB < 100MB ✅      │
                 └──────────────────────────────────────────────────┘
```

三个词概括整个项目:**"运动优先 + 检测定位 + 单模态达标再集成"**。

# 第二部分:全局规划思路与完整试错史

## 2.1 方法论三原则(整个项目的"宪法")

这是从无数失败中提炼出来的三条原则,后面每一个设计决策都能回溯到这三条:

- **P1 运动优先**:动作的本质是"身体随时间的运动模式",**时序建模是一等公民**。不能把动作识别当图像分类做(只看单帧=学外观=过拟合特定人)。
- **P2 检测定位、裁剪保运动**:目标检测只负责回答"人在哪";裁剪时用**多帧并集得到的一个固定窗口**,保留"人在画面中移动"的全局位移;**绝不逐帧裁剪**(逐帧跟着人裁 = 把位移运动抹掉了)。
- **P3 模态按硬件对齐分组**:同相机 → 早融合(拼通道);异源 → 独立建模 + 晚融合(集成)。**不搞 6 模态大杂烩联合训练**(历史上证明:6 模态联合 32% < 单模态 Thermal 37.85%)。

## 2.2 完整时间线(每一次关键试错,以及它教会我们什么)

这一节是整个项目最有价值的部分——**真正的工程能力不是"一遍做对",而是"每次做错能定位根因"**。

### 阶段 A:Wave 1 —— 第一次误判(把数据泄漏当成了成绩)

- **做了什么**:多模态 concat 融合 + TSM,mixed random split 划分数据。
- **结果**:本地 val 54.33%,沾沾自喜;提交 LB **32.8%**。
- **根因**:随机划分 clip 时,**同一个人的不同片段同时出现在训练集和验证集**。模型学会了"认人/认房间"(身份捷径),而不是"认动作"。21.5% 的差距就是泄漏量。
- **教训**:跨被试任务必须按 **subject 分组做交叉验证**。这条教训直接催生了 `src/split.py`。

### 阶段 B:基线摸底(诚实面对真实难度)

- **E0 基线**:TSM-ResNet18 + Depth/IR 4ch + 无裁剪 + 16 帧 + 3 折 = **36.15% ± 1.47%**。
- 这是最弱的真实 cross-subject 水平,后面所有消融都以此为准绳(相对提升,不看绝对数字)。
- 同期探索出:**论文 cross-subject 最优也只有 ~56%(SOTA ~60%)**,那些 90% 的论文数字是随机划分的虚高——**我们的 0.73 已经超过论文 cross-subject 水平**。

### 阶段 C:主干升级 + 两条作废的消融

| 实验 | 结果 | 结论 |
|------|------|------|
| E7:R2+1D-18 替换 TSM | 0.4618(+10%) | ✅ 分解卷积时序建模更强 |
| E1:+YOLO 固定裁剪 | 0.5033(+4%) | ✅ 检测定位有效 |
| E4:+帧差通道(4→8ch) | 0.5339(+1.7%) | ✅ 显式运动有效(仅当时 18 层骨干) |
| IR Otsu 人像掩码 | 0.2734 | ❌ 抹掉了背景运动上下文,作废 |
| 32 帧采样 | 0.3305 | ❌ clip 平均只有 ~29 帧,重复帧无益 |

### 阶段 D:R2+1D-34 + IG-65M 的第一次失败(教科书级教训)

- **做了什么**:升级到 63M 的 R2Plus1D-34,加载 IG-65M 大规模视频预训练权重,lr 用默认的 1e-3。
- **结果**:0.4252,反而比 18 层(0.53)差。
- **初步误判**:"模型容量太大,小数据过拟合"。
- **真正根因(后来才定位)**:lr=1e-3 对 30M 小网络微调没事,但对 63M + 精细预训练权重是**毁灭性**的——一大步梯度直接把 IG-65M 学到的通用运动特征冲垮,退化成从零训练。改成 lr=1e-4 后:**0.4252 → 0.5988(+17%)**。
- **教训**:① 预训练模型的微调,大模型要用小 lr;② 不要把"容量问题"当成结论,先查训练超参。

### 阶段 E:Scheduler 陷阱(CosineAnnealing 衰减到零)

- **现象**:后续多次实验(双流融合、多任务、骨架)训练到后半段完全不学习,lr 衰减到 3.94e-07 ≈ 0。
- **教训**:`CosineAnnealingLR(T_max=epochs)` 会把 lr 在最后归零,**后半程基本不更新**。统一改成 `StepLR(step=10, gamma=0.5)`(或保证 lr 不衰减到 0)。
- **⚠️ 反例修正**:后来在骨架线上发现,把 Cosine 改成 StepLR **反而降低基线**(0.5447 → 0.5113)。**结论:scheduler 不是普适铁律,transformer 类骨架更适合平滑衰减的 Cosine**。这提醒我们:每条"经验"都要标注适用边界。

### 阶段 F:跨折状态泄漏(假象 0.98 的幽灵)

- **现象**:MotionBERT 骨架 3 折 val = [0.4553, 0.9090, 0.9882]。fold1/fold2 高到不真实。
- **根因**:`model = ActionNet(...)` 写在 fold 循环**外面**,fold 之间复用了同一个模型 → fold1 的验证被试在前一个 fold 训练时已经被看过。
- **教训**:① **跨折循环必须每折重建模型**;② 诊断信号 = **折间方差巨大 = 泄漏/状态复用**。

### 阶段 G:SWA 权重平均导致预测塌缩(LB 0.39 → 0.62 的惊魂)

- **做了什么**:三折模型用 `--average` 做**权重平均(SWA)**合并成一份再提交。
- **结果**:测试预测**塌缩到 26 个类**(正常应 38-39 类),LB 0.39。
- **根因**:把 3 个在不同数据上收敛到不同决策边界的模型做**权重平均**,相当于把三个峰值不同的山平均成一片平原 → 决策边界模糊。
- **修复**:每折**独立打包 + 推理时 logits 平均**。LB 0.39 → 0.62。
- **铁律**:多折集成**只用 logits(输出概率)平均,绝不用权重平均(SWA)**。

### 阶段 H:冲刺成功,全量训练 + 多 seed 集成 = 0.71144

- **关键洞察**:0.711 公开方案用 2 折,每折模型只见过一半(9 个)被试。方法论定稿后,用**全部 18 被试(2931 clip,+45% 数据)训练**最终模型,大概率超越。
- **结果**:
  - 单 seed42 全量 = 0.70646 LB
  - seed42 + seed777 集成 = **0.71144 LB**(777 是互补的好 seed)
  - seed42 + seed2024 = 0.68656(2024 拖累,**弃用**)
- **教训**:全量训练没有 val(数据全用来训了),**seed 质量只能靠提交 LB 试错,只集成"不拖累"的 seed**。

### 阶段 I:第二模态 Thermal 的价值——从"拖累"到 "+1.86pt"

- **早期**:朴素地把 Thermal/Skeleton 加进集成,**反而拖累 main**(无泄漏 val 0.566 < main 0.59)。
- **后来发现**:拖累不是因为 Thermal 没用,而是**Thermal 的训练 recipe 落后**。修复两个点:
  1. **归一化 bug**:Thermal 之前用 ImageNet 均值归一化,但模型是 IG-65M(Kinetics 域)→ 换回 Kinetics 归一化。
  2. 补全 crop + 类平衡 + 增强 + label smoothing 全套 recipe。
- **结果**:Thermal fold0 0.5646 → 0.6190(+5.4)。
- **最终融合**:main_s42 int5 + thermal_s42 int5 = 80MB,prob 平均 + flip TTA = **LB 0.73**(+1.86pt vs 0.71144)。**"1×main + 1×thermal 独立视角" > "2×main 两个 seed"**——独立视角的互补性大于同视角的多样性。

### 阶段 J:"花哨方法 < 朴素平均"的连续验证(最重要的战略结论)

三次有明确文献背书/精心设计的方法,全部败给最简单的概率平均:

| 方法 | 机制 | 结果 |
|------|------|------|
| 跨模态对比学习(main↔thermal) | InfoNCE 对齐模态表征 | s2 fold0 -1.7%(负收益) |
| 伪标签全量自训练 | 用测试同分布数据扩训练 | LB 0.69651(< 0.73) |
| 类感知/置信门控融合 | 每类动态调模态权重 | LB 0.64(< 0.73) |

**结论**:main_s42 + thermal_s42 的朴素 prob 平均是最强、最稳健的提交。本质原因:**main 与 thermal 是同质视觉模态,错误高度重叠,融合可挖掘空间很小,任何"学参数"的融合都是在小数据上过拟合**。

### 阶段 K:系统穷尽后的最终判定

损失层面(ArcFace 崩、CenterLoss 中性)、融合层面(特征级 dual_fusion 0.6114、MISA 0.3692)、骨架层面(清洗有害、part-aware 有害)、IMU(0.35 天花板低)——**全部关闭**。结论:**0.73 是这套框架 + 数据量 + 约束(2891 同域样本 / 100MB / RGB-Free / 跨被试)下的强上限**。

## 阶段 0:数据探索 —— 不写代码,先摸清数据

**写了什么**:一批探索脚本(`scripts/explore/` 下,已归档)、关键事实沉淀到 `memory` 与 `doc/`。

**做了什么**:
1. 数清规模:训练 2891 clip(不是文档里 17503——那是 6 模态 trial 合计的误导)、测试 405、18 被试、40 类。
2. 逐一核对每个模态的**文件格式**:Thermal 是 3ch 伪彩色 jpg(不能转灰度)、Depth_Color 是 jet 伪彩色 png、IR 是 1ch 灰度、Skeleton 是 `predictions/*.json`(17 关节 × [x,y,z] + 置信度)、IMU 是 2 个 csv、Radar 是点云 csv。
3. 算出缺失率、帧率、长尾比。
4. **最关键的一步**:从论文硬件章节反推出"哪几个模态在同一台相机上"——这决定了后面所有融合策略。

**为什么先做数据探索**:绝大多数项目失败在"数据和假设对不上"。
- 例:想当然以为 Depth_Color 是自然 RGB,就会用 ImageNet 预训练,但它是 **jet 伪彩色深度图**(B-R 通道相关系数 -0.69、G 均值 186),语义是"深度几何"而非"自然外观" → 预训练只能做**结构迁移,不是外观迁移**。
- 例:想当然以为骨架是像素坐标可以拿来裁图,但它是**3D 米制坐标** → 只能独立建模。

> **旁白(方法论):数据探索的四个必查项** = ① 规模与类别分布(决定采样策略)② 每个样本的物理格式(决定预处理)③ 缺失/坏数据比例(决定要不要清洗)④ 数据产生的**硬件/采集方式**(决定哪些数据可以对齐融合)。第④点最容易被忽略但最致命。

## 阶段 1:划分与评估协议 —— 先修好"尺子",再量"身高"

**写了什么**:`src/split.py`(`split_by_subject`)。

**为什么这是第一块要写的核心代码**:
- 跨被试任务的评估必须是:**按被试(subject)分组,同一被试的所有 clip 要么全在训练集、要么全在验证集**。
- 18 个被试 → 3 折,每折 6 人做验证,并且代码里带**防泄漏断言**(`assert train_subjs.isdisjoint(val_subjs)`)。
- 后面所有"要不要上这个模型/这个增强"的判断,都建立在这把"不撒谎的尺子"上。

> **旁白(方法论):为什么随机划分会虚高** —— 人体动作数据里,"谁来做的"信息量远大于"做了什么"。如果同一个人的片段泄漏到验证集,模型只要学会"这是张三,张三走路时总是这个姿势",就能用身份特征拿分。正确的 cross-subject 划分,本质是逼模型学**与身份无关**的表征。这也是为什么 later 用 ArcFace/对比学习这些"跨身份泛化"技巧(人脸识别的核心)来冲高分。

## 阶段 2:单模态主线 —— Depth+IR 4ch 早融合 + 视频模型

**写了什么**:
- `src/dataset.py`:`DepthIRVideoDataset` —— 按帧号把 Depth_Color(3ch) 与 IR(1ch) 拼成 `[T,4,H,W]`,endpoint-uniform 采样 16 帧,缺帧补零。
- `src/model.py`:`R2Plus1D18` / `R2Plus1D34` —— 视频主干 + `adapt_conv3d` 把 3ch stem 改成 4ch。
- `scripts/train_step1.py`:`train_fold` / `evaluate` / `main` —— 训练循环 + 3 折交叉验证。

**关键决策与为什么**:

1. **为什么 Deep+IR 拼通道(早融合)而不是分开**:它们来自同一台相机、帧号天然对齐,拼成 4ch 让网络在**最底层同时看到"深度几何 + 红外剪影"**,能学到互补的局部特征。异源模态(如 Thermal)没有这种对齐,才需要晚融合。

2. **为什么选 R(2+1)D 而不是 TSM/普通 3D CNN**:消融证明 R2+1D-18 比 TSM-ResNet18 高 10%。因为(见旁白)分解卷积用更少的参数量、更好的优化性,把空间和时间卷积分开学,时序建模更强。

3. **stem 怎么从 3ch 改 4ch**:`adapt_conv3d` 复制前 3 通道的预训练权重,新增的第 4 通道用**前 3 通道权重的均值**初始化。这样不破坏预训练,又多容纳一个通道。**新增通道用均值而不是随机 = 保证初始化时新通道的输出量级与预训练一致,不会打乱网络。**

> **旁白(方法论):预训练迁移的两种情形**
> - **外观迁移**:自然图像 → 自然图像,权重可直接复用(如 Thermal 铁 bow 伪彩色 ↔ IG-65M 3ch,stem 不用改,100% 迁移)。
> - **结构迁移**:伪彩色深度图 ↔ 预训练的 Kinetics 自然视频,语义错配,但**低级边缘/纹理/运动检测器**仍通用,所以只保留 stem 以上层,低级层复制权重 + 微调。

## 阶段 3:检测定位 —— YOLO + 固定窗口裁剪

**写了什么**:
- `src/detect.py`:`load_yolo` / `detect_clip` / `window_from_boxes`。
- 离线跑出 `bbox_train.json` / `bbox_test.json`(缓存,训练/推理直接读取)。

**做了什么**:
- **在 IR 上检测而不是 Depth/其他**:IR 是主动红外的人体剪影,对比度最高、受房间环境干扰最小,YOLO 检测率 99%(训练)/ 97.5%(测试)。
- 检测流程:**多帧(8 帧均匀)探测 IR → 取所有框的并集(union) → 放大 1.4x → 转正方形 → 全程用这一个固定窗口裁剪所有帧**。

**为什么固定窗口这么重要**:
- 如果逐帧检测再逐帧裁剪 = 窗口永远贴在人身上 → 网络看不到"人从画面左边走到右边"的**位移运动**,学到的空间信息反而被抹平。
- 固定窗口保留了身体的**全局运动轨迹**(位移),这正是动作识别最核心的线索之一。

> **旁白(方法论):检测与识别的分工** —— 检测只回答"哪里有人"(定位),识别回答"在做什么"(分类)。两者不该耦合:检测输出一个**稳定的窗口**,让识别网络在一个**固定坐标系**里观察运动。这也是 0.711 公开方案的核心 trick 之一。

## 阶段 4:训练细节 —— 类平衡、增强、label smoothing

**写了什么**:`train_step1.py` 里集成了这些开关:`build_balanced_sampler`、`aug_strength`(0/1/2/3 档)、`--label_smoothing`、`--full`。

**四项关键训练设定与为什么**:

1. **类平衡采样(WeightedRandomSampler)**:长尾比 29.5,如果直接随机采样,模型会被 Walk(324 个)淹没,少数类学不到。对每个类按样本数加权采样,保证每类在训练时被均匀看到。

2. **数据增强(aug_strength=2,定版)**:随机水平翻转 0.5 + 亮度/对比度 0.8~1.2 + 缩放 0.85~1.15 + 平移 ±8%。消融显示 aug0 → aug1 提升 +4.7pt(过拟合明显),aug2 多折验证最优。**增强在小数据上是比任何花哨结构更有效的过拟合抑制器**。

3. **label smoothing 0.1**:软标签校准置信度,对后面的 logit 集成有益(过自信的模型与欠自信的模型融合质量差)。零风险,一行就能加。

4. **`--full` 全量模式**:最终冲刺时用全部 18 被试训练、不分折、无 val,靠 Cosine 退火收敛后取最后 epoch。**为什么**:2 折方案每折模型只见过 9 人,全量数据 +45%,几乎免费提升。

> **旁白(方法论):增强强度这个旋钮怎么调** —— 小数据下增强不是"越大越好":太弱 → 过拟合;太强 → 引入训练分布里没有的假象(比如把深度图亮度改得太离谱,破坏了"距离→颜色"的物理对应)。所以用 `aug_strength` 分档做消融,而不是拍脑袋。

## 阶段 5:升级骨干 —— R2+1D-34 + IG-65M(为什么能涨 +7%)

**写了什么**:`src/model.py` 里的 `R2Plus1D34` + `scripts/train_step1.py` 加 `--backbone r2plus1d34 --weights <IG-65M>`。

**关键点**:
- 63M 参数、layers=[3,4,6,3] 的 ResNet 风格 3D 网络,加载 **IG-65M** 预训练权重。
- **IG-65M** 是什么:Instagram 6500 万视频上用自监督学的视频表征,再在 Kinetics-400 上微调,是当年**最强的小型视频预训练**。
- 单独看模型大小超了 100MB,所以后面必须量化。
- **决定性细节**:lr 必须是 1e-4(前面阶段 D 的教训),否则预训练权重被冲垮。
- 还要修一个 `_Conv2Plus1D` 的 midplanes 公式,因为老版 IG-65M 权重和当前 torchvision 的 midplanes 计算不一致,不修会尺寸对不上(load_state_dict 会报错)。

> **旁白(方法论):为什么预训练权重如此值钱** —— 2891 个 clip 对 63M 参数的网络是"小样本",从零训练必然过拟合。预训练给了一个"已经见过几千万种运动模式"的起点,微调只需要让它适应这 40 类的具体语义。这正是"小数据 + 大预训练模型"范式(现在的大模型微调也是同一套逻辑)。

## 阶段 6:第三模态骨架——"预训练胜过自己从头练"(ST-GCN → MotionBERT)

**写了什么**:
- `src/skeleton_dataset.py`:`SkeletonVideoDataset`(输出 `[T,17,6]` = xyz + 速度)、`MotionBertSkeletonDataset`(输出 `[T,17,3]`,原生 3D 输入)、`build_skeleton_index`、`random_moving` 增强、`--clean`/`--norm` 选项。
- `src/motionbert/`:`dstformer.py` + `action_net.py`——**自包含实现**了 MotionBERT(ICCV 2023),Apache-2.0,不依赖外部库。
- `scripts/download_motionbert.py`:从 HF 镜像下载 MB_lite / NTU 预训练权重(带重试,大文件下载 DNS 抖动)。
- `scripts/train_skeleton_motionbert.py`:3 折微调,`load_pretrained_backbone` 能同时解析 `model_pos`(预训练)/ ActionNet(NTU 动作权重)两种权重格式,并按 `joints_embed.weight` 的实际维度自动判断 lite / release 架构。
- 一系列骨架变体:`train_skeleton_augmented.py`(混合 NTU 数据 + `--clean`/`--part_aware`/`--task_prior_part` 开关)、`train_skeleton_multitask.py`(共享 backbone + 双头)、`src/ntu_dataset.py`(NTU-60 25→17 关节映射),外加一批 `.sbatch`(清洗、part-aware、torso、3D 对照等)。

**先理解骨架这个模态的特殊性**:
- 它在 `Skeleton/<Action>/<Subject>/<sample>/predictions/*.json`,每个 json 是一帧的 17 个关节 `[x,y,z]` + 置信度。
- 拓扑是 **Human3.6M-17**(0 骨盆 / 1-3 右腿 / 4-6 左腿 / 7-10 躯干头 / 11-13 左臂 / 14-16 右臂),**不是**更常见的 COCO-17。
- 坐标是 **3D 米制坐标**(z 是到地面高度,0~2.27m),**不是像素**。这一点决定了:骨架不能拿去裁图像,只能独立建模。
- 置信度通道经全量扫描**恒为 1.0**(MMPose 输出退化),所以 ST-GCN 输入从 7ch 减到 6ch;MotionBERT 的输入是固定的 `[x,y,conf]` / `[x,y,z]`,conf 恒 1.0 无害,直接忽略。

**两条技术路线,以及为什么最终选了 MotionBERT**:

1. **ST-GCN(早期,0.3479)**:图卷积在"关节×时间"图上做时空卷积,是骨架动作识别的经典基线。我们用修好的 H3.6M-17 边集(不能用 COCO 边集)实现了 joint + bone 双流。成绩 ~0.35,是三个模态里最弱的。
2. **MotionBERT(最终,0.4177)**:**这在 CVPR/ICCV 之外是"骨架界 BERT"**——在一个大规模 3D 人体运动库(H36M + AMASS,几千万帧)上做遮蔽建模预训练,学到的身体运动先验非常通用。把预训练的 DSTformer encoder 换掉随机初始化的图卷积,等于把"怎么动才是合理的人"这个常识直接搬进来。**这就是"预训练胜过自己从头练"的最典型例子:2891 个样本对骨架这种高维时空序列来说太小,自己练的模型只记得"这 18 个人怎么动"。**

**为什么第 3 通道的表示能值好几个点(一个隐晦但致命的 bug 故事)**:
- 旧实现喂 `[x, y, conf]`,conf 恒 1.0——等于**把第 3 维当成常数,白白丢了原生深度**。而 MotionBERT 的预训练权重 `model_pos` 是在 **3D 数据(H36M/AMASS)** 上学的,喂 2D 表示 = 预训练知识全浪费 + 输入退化。
- 改用 `input3d=True`(`[水平, 垂直, 深度]`,中心化 + 肩宽归一化)后,3D 预训练知识才真正迁移进来。**这是一个"表示(representation)错了,后面的模型再强也没用"的经典案例**——面试特别有讲头。

**预处理三件套(为什么)**:
1. **中心化(减骨盆)**:消除绝对位置。绝对坐标本身就是"身份/房间捷径"(谁站在房间哪里),跨被试必须去掉。
2. **尺度归一化(除以肩宽)**:不同人身高体格不同,除以一个"自身固有长度"把骨架缩放到统一体型。后期还试过"骨盆-颈"的 torso 长度(0.711 notebook 建议,比肩宽更稳,因为躯干是一个长尺度、不易被两个关节的噪声污染)。
3. **`random_moving` 增强**:首末帧各采样一组旋转/平移/缩放,中间线性插值——**模拟相机在平滑移动**。这是 ST-GCN 论文 §3.6 的手法,让模型对"视点变化 + 相机抖动"鲁棒,是很聪明的物理合理增强。

> **旁白(方法论):为什么骨架的跨被试成绩难看但仍然是"强模态"**
> 论文里骨架随机划分能到 79%,但我们 cross-subject 只有 0.45。这不是没做好,而是 **cross-subject 本身就会让所有模态蒸发 30+ 个点**(RGB 90.89% → 56.38%,骨架 79% → 45%,掉幅一致)。**0.45 ≈ 骨架在这种评估协议下的天花板**,面试被问"骨架怎么这么低"时,这个回答能把劣势变成"我理解评估协议"的优势。

## 阶段 7:第二视觉模态 Thermal——独立相机 + 同构迁移

**写了什么**:
- `src/dataset.py` 里 `ThermalVideoDataset` / `build_thermal_index`:3ch 伪彩色视频,~25fps,无缺失。
- `src/detect.py --modality thermal`:YOLO 在 **Thermal 帧**上检测人 → 生成 `bbox_thermal_train.json`(复用红外检测能力,效果也不错)。
- `scripts/train_step1.py --modality thermal`:直接复用主线的训练循环,只是数据集换成 Thermal。

**为什么 Thermal 是"第二视觉模态"而非"第三模态"**:
- 它是独立热成像相机(Hikvision),**不与其他任何模态共享坐标系**(骨架/深度/IR 都在 NYX 650 视场内,Thermal 不在)。
- 但它是 **3ch 伪彩色图像**(ironbow 色带),和 R2+1D-34(IG-65M)的 **3ch 输入天然完美匹配——stem 一行都不用改,100% 预训练权重迁移**。这是"同构迁移":虽然色带语义不同,但低级边缘/纹理/运动检测器是通的。

**两个关键修正是 Thermal 从"拖累"变"增量"的分水岭**:
1. **归一化 bug**:Thermal 之前用 ImageNet 均值(0.485, 0.456, 0.406)归一化,但我们的模型是 IG-65M(Kinetics 域),归一化域不匹配会让预训练权重"看"到的输入分布完全不对。换成 Kinetics 均值(0.43216, ... )后,单这一项就贡献了大部分提升。
2. **补全套 recipe**:thermal YOLO crop + 类平衡 + 增强 + label smoothing——把 main 上验证过有效的训练配方原样搬到 Thermal 上。
3. **帧差对 Thermal 有害**:帧差(3→6ch)与 IG-65M 预训练的 3ch 输入互斥,而且热力的帧间噪声大,语义错配,所以 Thermal 定版固定 3ch。

**成绩**:fold0 0.5646 → **0.6190**(+5.4pt,单靠 recipe)。这是当前性价比最高的"未充分利用资产"——论文里 Thermal 随机划分是所有模态最高的(92.57%),说明它本身信息量大,差距一直在 recipe 上。

> **旁白(方法论):"模态没有用"往往只是"recipe 没用上"**
> 早期我们把 thermal/skeleton 朴素加进集成,**拖累**了 main(0.566 < 0.59)。当时的结论是"弱模态没用"。后来发现:拖累的真正原因是**它的训练 recipe 落后**(归一化错、没 crop、没增强),不是模态本身。**在关闭一个模态之前,先把它喂到跟强模态同等的训练质量,才有资格下结论。** 这一点对面试的杀伤力极大。

## 阶段 8:量化打包——把权重塞进 100MB

**写了什么**:
- `src/quantize.py`:**per-output-channel 量化/反量化** + int5/int6 **bit-packing**(位压缩)。
- `scripts/quantize_pack.py`:训练好的 fp32 checkpoint → 打包成 `<name>_fold{i}_int{bits}.pth`,并**自动统计总大小、检查 <100MB**。
- `scripts/pack_full.sbatch`:全量训练模型的打包入口。

**为什么必须量化(数学账)**:
- R2+1D-34 = 63M 参数,fp32 = 247MB,**单个就超 100MB**;更别说要集成多个模型。
- 唯一路线 = 量化。per-output-channel:对每个输出通道按它自己的绝对值最大值算 scale,把权重从 fp32(4 字节)压到 int8(1 字节)甚至 int5/int6(bit 级);
- 规则澄清后确认:**100MB = 推理时加载的全部权重打包大小,量化明确允许**——所以这不是"取巧",是把预算花在刀刃上的正道。

**量化还要做减法——"只量化大张量"**:
- bias / BN / 小张量**保持 fp32**(数量少、占比小、对精度敏感)。只量化 Conv/Linear 的 weight 这种大块(>4096 元素)。
- 实际体检:`main int5(40MB) + thermal int5(40MB) = 80MB`,留出 20MB 余量,合规。

**int4 为什么崩(量化误差放大到分类崩溃)**:
- 提交级实验证明:R2Plus1D 这种网络 **int4 直接把精度打崩**(LB 0.71 < int5 的 0.73)。原因是 int4 的量化步长太大,把"不同类之间本来就接近"的 logits 差异碾平,分类边界直接瓦解。
- 铁律:**R2Plus1D 提交级最低 int5**。这也是为什么我们敢在 100MB 预算里硬塞两个 int5 模型——因为这是"最接近崩的极限"。

> **旁白(方法论):量化是"精度-体积"的工程权衡,不是无脑压缩**
> - 对称 per-channel 量化:每输出通道一个 scale,`q = round(w / scale)`,反量化 `w ≈ q * scale`。
> - int8 → int5 的压缩收益接近线性(int5 只有 int8 的 62.5%),但精度损失在"分类边界是否还分得开"这个临界点上突然显现(phase transition)。
> - 我们的策略 = **在崩之前取最大压缩**(int5),把省下的体积用来**多放一个独立视角的模态**。面试官问"Asymmetry/动态量化/蒸馏感知量化"时,能讲清楚这个权衡就够起步了。

## 阶段 9:集成推理——从"三模态加权"到"朴素概率平均"

**写了什么**:
- `scripts/ensemble_inference.py`(你现在打开的这个):多模态推理 + 多折/多 seed logits 平均 + 翻转 TTA + 概率平均 + 自动权重 + 量化加载(反量化)+ v3 bounded-prior 实验 + Noisy-OR 实验。
- `scripts/fusion_validate.py`:**在 val 折上**用同折 checkpoint 验证"融合到底能不能救回 main 的错"——输出各模态单独 acc、各种融合方式 acc、**oracle 完美选择上限**(如果每样本都能选对模态,最高能到多少)。
- 早期尝试:`dynamic_fusion.py`(样本级动态加权)、`fusion_class_gated.py`(类感知/置信门控)。

**集成方法论在这里经历了完整的"失败 → 理解 → 收敛"过程**:

1. **三模态 logit 加权(早期)**:main + thermal + skeleton 按 val acc 加权平均 → **反而拖累**(无泄漏 val 集成 0.566 < main 单模态 0.59)。原因:skeleton 0.45 太弱,且与 main **错误高度重叠**(都是看同一个人的视觉线索)。
2. **两个证明"融合空间很小"的实验**:
   - **oracle 分析**:即使每样本都完美选择最佳模态,上限也只有 ~0.68-0.71,并不比 main 高多少——**说明 thermal/skeleton 的错误和 main 的错误重叠严重,朴素平均救不回多少**。
   - **类感知/置信门控(0.64)**:用"见过 val 的模型"在 val 上拟合每类的模态权重,val 上 1.0(假象)、测试上失效——**这是用小数据拟合记忆参数,严重过拟合**。
3. **结论收敛为"朴素 prob 平均 + flip TTA"**:main_s42 + thermal_s42,softmax 后加权限平均。**为什么是概率平均不是 logits 平均**:不同模型 logits 的尺度/偏置不一致,直接相加会被"嗓门大的模型"主导;softmax 后统一成概率尺度,融合更稳。这就是 `--prob_avg` 存在的意义。

**关于 `--auto_weight` 的旁注**:用 val acc 的 softmax 自动设权重——思路对(好的模态权重大),但实践中最终还是等权概率平均最稳,因为一旦开始"调权重"就又回到"在小 val 上过拟合"的老路上。

> **旁白(方法论):如何科学地判断"融合是否有价值"——互补性分析**
> 融合的收益不取决于"每个模态多准",而取决于**两模态的错误分布是否互补**。标准做法:
> ① 在 val 上分别推理各模态;② 统计"B 的预测能纠正多少 A 的错"(rescue 量)和"B 引入多少 A 本来对的错"(corruption 量);③ 算 oracle(每样本选最佳)= 融合上限。
> 我们实测 rescue 0.18-0.25 / oracle 0.68-0.71,而 main 自己 0.71 → **结论:没有融合空间,别硬融合**。这套"先用 oracle 算清天花板,再决定投不投入"的分析方法,是面试官非常想听到的科学决策流程。

## 阶段 10:全量训练冲刺——数据量 +45%,多 seed 集成(0.71144)

**写了什么**:
- `scripts/train_step1.py` 加 **`--full` 模式**:全部 18 被试 2931 clip 一起训练、不分折、不评估 val,靠 CosineAnnealing 退火收敛后取最后 epoch。
- `scripts/run_full_main.sbatch`:全量训练入口(seed42 / 2024 / 777 各训一个)。
- `scripts/test_submission.sh`:统一测试脚本,`CUDA_VISIBLE_DEVICES="" bash scripts/test_submission.sh "42 777"` 在登录节点 CPU 上自动完成"打包 → 推理 → 校验"。

**为什么要全量(一个很强的数据洞察)**:
- 公开 0.711 方案用 2 折,每折模型只见过 9 个被试(另 9 个留 val)——**首轮最终提交的每个模型其实只见过一半的人**。
- 方法论定稿后,把类别平衡 + 增强 + label smoothing 这套"被验证过"的配方作用于全量数据(2931 clip,比任何折的方案多 45% 数据) → 单 seed42 就到 **0.70646 LB**。

**多 seed 集成的教训(全量无 val 的代价)**:
- 全量训练没有 val 可以选模型,seed 好不好"只能靠提交 LB 试错"。
- seed42 + seed777 集成 = **0.71144**(777 与 42 的预测错误互补,理想组合);
- seed42 + seed2024 = 0.68656(2024 拖累,弃用)。
- **铁律:只集成"不拖累"的 seed**——这和"只集成不拖累的模态"是同一个原理:集成是**风险分摊**,不是"越多越好"。

**aug_strength 组合搜索(为什么定版 = 2)**:
| aug_strength | fold0 | 结论 |
|---|---|---|
| 0(无) | 0.6179 | 过拟合明显 |
| 1(温和) | 0.6652 | fold 上最优 |
| 2(当前强) | 0.6609 | **定版**(全量实测最稳) |
| 3(更强) | 0.6609 | 与 2 持平,收益饱和 |

- **一个沉重教训:fold 结论不能映射全量**。aug_strength=1 在 fold 上最优(fold0 0.6652),但**全量 + aug1 只到 0.652(失败)**;aug2 全量 0.706 才稳。原因:fold 有 val 早停、数据分布与全量不同。**"用小实验选出的超参,大实验未必成立"——所以定版超参必须再经全量验证一次。**

> **旁白(方法论):为什么要用 seed 或 fold 来"重复实验"并做集成**
> 单个模型训练是随机过程(数据采样、增强扰动、权重初始化),单次结果方差很大。用不同 seed(或不同 fold)重复训练,推理时把各模型的**输出概率平均**:
> - 能压低方差(多个弱相关估计平均,误差期望下降);
> - 只有当两个模型的错误**互补**(不重叠)时,平均才真正涨点——所以 seed42+777 有效而 +2024 无效。
> 集成是"用算力换鲁棒性",在竞赛里几乎是免费的最后一手,但**永远要先验证互补性再采信**。

## 阶段 11:Thermal 升满 recipe + 决策级融合 → 0.73(最终成绩)

**做了三件事,把 0.71144 推到 0.73**:

1. **Thermal 全量 + 双 seed(独立视角的强副模型)**:把阶段 7 修好的 recipe(main 同款增强/类平衡/label smoothing/Kinetics 归一化)用到 Thermal 全量训练上,得到 ~0.63 的 Thermal 副模型。
2. **预算重排**:赛制 100MB 预算下,"main int5(40MB)+ thermal int5(40MB)"正好 80MB。
3. **概率平均融合 + 翻转 TTA**:`main_s42 int5 + thermal_s42 int5`,prob 平均 + flip TTA → **LB 0.73(+1.86pt)**。

**最关键的战略结论(面试必讲)**:
> **"1×main + 1×thermal(独立视角)" > "2×main(两个 seed,同视角)"**
- 同一视角的两个模型(main+main)错误高度重叠,平均只能压方差;
- 不同物理视角的两个模型(main+thermal)错误**天然互补**(深度几何 vs 热辐射),平均既能压方差又能补盲区。
- 这正是多模态项目"质量优先于数量"的实证:**模态的价值 = 信息独立性,不是个数**。

> **旁白(方法论):多模态融合的三个层次(面试高频考点)**
> ① **数据级/早融合**:模态需要天然对齐(同相机、同帧、同坐标系)才能在输入端拼通道——我们有 Depth+IR 4ch。
> ② **特征/模型级融合**:双流网络中间层交互(注意力、门控),成本高、需要配对数据,我们实测在小数据上反而差(dual_fusion 0.6114 < 决策级)。
> ③ **决策级/晚融合**:各模态独立出 logits/概率再融合——最稳、最抗错对齐问题、最容易增量式扩展,我们最终采用它。
> **选择规则:能早融合的前提是"硬对齐",没有硬对齐就老老实实晚融合。**

## 4.1 视频理解的时序建模演进:2D+时序 / 3D CNN / R(2+1)D / TSM

**问题**:动作是"视频",但 2D CNN 只能看单帧。怎么把时间加进去?

- **TSM(时序移位)**:把输入的帧序列在通道维度上"错位移动"——`out[:, :-1, :fold] = x[:, 1:, :fold]`——用**零参数的 2D 网络**模拟"看到前后帧"。思想:通道分块,一部分往前挪、一部分往后挪,2D conv 天然就混合了相邻帧的信息,等价于廉价的时序建模。轻、快,是 2D 竞赛标配。
- **3D CNN**:卷积核从 2D `(k,k)` 变 3D `(t,k,k)`,直接同时卷空间+时间。信息最完整,但参数爆炸、优化难。
- **R(2+1)D(我们最终选的)**:**把 3D 卷积分解成两个子卷积**——先做 1×3×3(纯空间),再做 3×1×1(纯时间)。为什么好:
  - 参数量下降(分解让两个子任务各用更小的核),正则化效果(强制网络"先理解空间、再理解时间");
  - **优化更容易**(中间多了 ReLU,缓解退化);
  - 消融直接验证:R2+1D-18 比 TSM-ResNet18 高 10 个点。

**删除线法则**:选时序建模器时,先用消融说话。我们最初的 E0 是 TSM,E7 换 R2+1D 立涨 10%。

## 4.2 目标检测与"定位-识别"解耦(YOLO + 固定窗口)

**问题**:视频里人可能很小、在移动,直接把整帧喂网络会浪费大量像素在背景上。

- **YOLO(You Only Look Once)**:把检测当回归一次完成——把图片分成网格,每个格子直接回归"有没有物体 + 框 + 类"。one-stage、极快,足够在每帧上跑。
- 我们的做法是 **"检测 = 定位,识别 = 分类"的解耦**:YOLO 只在 IR 上找人(IR 剪影最清晰,99% 检测率),输出一个框;**多帧的框取并集 → 放大 1.4x → 转正方形 → 全程一个固定窗口裁所有帧**。
- **为什么固定窗口而不是逐帧裁剪(本项目最重要的思想之一)**:
  - 逐帧裁剪 = 窗口永远贴着人 → 网络看不到"人从画面左走到右"的**位移** → 空间运动信息被抹平;
  - 固定窗口 = 网络在一个**固定坐标系**里观察身体运动,位移成为可见特征。
- 这套"检测只负责人在哪、识别只看运动"的分工,是把动作识别做好的普遍 trick。

---

## 4.3 跨被试评估与"身份捷径"(subject-split / 防泄漏)

- 人体数据集里,"谁来做的"信息量远大于"做了什么"。随机切分会让同一个人的片段同时出现在 train/val,模型学会"这是张三,他在客厅走路"的**身份/房间捷径**——本地 val 虚高 21.5%。
- 正确做法(subject-split,`src/split.py`):**同一被试的所有 clip 要么全在训练集、要么全在验证集**,并带 `isdisjoint` 防泄漏断言。
- 这是"评估协议决定了你在优化什么"的教科书案例:**协议错了,所有的"提升"都是幻影**。

---

## 4.4 类别不平衡与类平衡采样

- 数据长尾比 29.5(Walk=324 vs Watch_TV=11),随机采样会让少数类完全学不到。
- **加权随机采样(WeightedRandomSampler)**:按类别样本数的反比加权,每个样本被抽到的概率与类规模成反比,让模型每轮看到的类别分布近似均匀。
- 代价:会让多数类略欠拟合——所以平衡是"宁可少数类多瞅几眼",对 40 类均匀目标是对的方向。

---

## 4.5 校准与标签平滑(Label Smoothing)

- 分类头用 CE 训出来的模型往往**过度自信**(logits 大、概率接近 0/1)。做集成时,过度自信的模型会"嗓门太大"主导融合。
- **Label Smoothing 0.1**:把 one-hot 标签改成 `0.9 * one_hot + 0.1/40 * uniform`,逼模型别赌太大,输出更校准的概率 → **对 logits/prob 集成友好**,几乎零成本的校准手段。

---

## 4.6 数据增强作为正则(小数据的命脉)

- 2891 个 clip 对大网络是极小样本,增强是比任何结构都有效的"过拟合抑制剂"。
- 我们的增强(按 `aug_strength` 分档):水平翻转 0.5 + 亮度/对比度 0.8~1.2 + 缩放 0.85~1.15 + 平移 ±8%。
- **增强强度不是越大越好**(太强会把"深度→颜色"的物理对应打坏),所以要分档消融:aug0→aug1 涨 +4.7pt(过拟合明显),aug2 全量最稳,aug3 饱和。
- 对伪彩色深度图要"保护物理语义"——亮度/对比度可动,但不能破坏距离编码关系。

---

## 4.7 预训练迁移:外观迁移 vs 结构迁移(stem 改造 / IG-65M)

- **外观迁移**:输入分布相近(自然图→自然图、Thermal 3ch→Kinetics),权重可直接复用,甚至 stem 都不用改。
- **结构迁移**:输入语义错配(伪彩色深度图≠自然 RGB),但**低级边缘/纹理/运动检测器依然通用**——保留 backbone,微调去适应。
- **stem 改造(`adapt_conv3d`)**:3ch→4ch 时,前 3 通道复制预训练权重,**新增通道用前 3 通道的均值初始化**(保证新通道输出的量级与预训练一致,不打乱网络)——比随机初始化稳得多。
- **IG-65M**:Instagram 6500 万视频自监督 + Kinetics 微调的小型预训练,是当年"小数据做大动作识别"的关键弹药。

---

## 4.8 调度器:Cosine 归零陷阱 vs StepLR(含适用边界)

- `CosineAnnealingLR(T_max=epochs)` 会把 lr 衰减到 ~0,**最后一半 epoch 基本不更新**。在双流融合/多任务上直接坑死训练(lr→3.94e-07)。
- 对策:统一 `StepLR(step, gamma)` 或保证不退到 0。
- **⚠️ 但边界很重要**:骨架的 transformer 移回 Cosine 反而更优(0.5447 vs 0.5113)。**同一个"经验"在不同架构上可能相反——经验要写适用边界。**

---

## 4.9 骨架表示学习:ST-GCN → MotionBERT

- **ST-GCN**:把骨架建成"关节×时间"图,边上权重可学习,时空卷积分类。经典但**零预训练**。
- **MotionBERT**:在大规模 3D 人体运动库(H36M+AMASS)做**掩码建模预训练**的 DSTformer(Swin 式 transformer),学到通用"人体运动先验"。用预训练 encoder 微调 = 把"人体运动常识"搬进来。这是骨架动作识别的 SOTA 范式(类似 BERT 之于 NLP)。
- **表示(representation)工程是骨架的命门**:
  - 中心化(减骨盆)去绝对位置;
  - 用肩宽/torso 归一化去体格差异;
  - **喂原生 3D(匹配 3D 预训练),不要喂 2D+常数 conf**(我们的 0.4pt 教训);
  - random_moving 旋转/平移/缩放增强模拟相机运动。
- **为什么要外部数据(NTU-60)**:单数据集 2891 样本对骨架太稀,NTU 有 37,920 个同域样本,但 25→17 关节映射 + 体积翻倍,收益仅 +0.34pt,不值。

---

## 4.10 对比学习与 CLIP 范式(InfoNCE)

- CLIP 的核心:正样本对(同一 clip 的两视角特征)拉近、batch 内负样本推开,用 **InfoNCE** 交叉熵对齐模态无关表征。
- 我们用它的动机:论文 §6.1.3 证明对比学习能提升 cross-subject 泛化(学模态不变的动作语义)。
- **为什么我们 s2 上 -1.7%(负收益)**:弱模态(thermal 0.56)去"监督"强模态(main 0.71)时,辅助损失的梯度方向与分类损失冲突,在有限数据上扰动强模态收敛——**Chebyshev:辅助监督的质量必须配得上主任务**。

---

## 4.11 伪标签与自训练(co-training)

- 无标签测试数据是**同分布**(比任何外部数据相关),官方允许伪标签。做法:main+thermal 双模型 Co-training(两模型预测一致的才采信)+ 动态 top-K 置信度筛选 + 低训练权重(可靠性加权)+ 单轮自训练防漂移。
- fold0 上微降(0.6566 vs 0.6609),全量+融合没烧 LB(唯一剩的合法大杠杆)。
- **思想**:伪标签把"测试分布"借给训练——但伪标签噪声会污染,需要"宁缺毋滥"的筛选哲学。

---

## 4.12 知识蒸馏(teacher-student)

- 用强模型(teacher, main 0.71)的软标签训练弱模型(student, skeleton 0.45),soft label 比 hard label 携带"类间相似度"信息。
- **我们的判断**:对 0.45 的骨架,蒸馏最多提到 ~0.5+,但骨架错误与 main 高度重叠,提升后**依然拖累**——所以"救弱模态"的路最终关闭。

---

## 4.13 多模态融合全景(早/特征/晚/决策 + 同质 vs 异质)

| 层次 | 机制 | 前提 | 我们的结果 |
|---|---|---|---|
| 数据级(早) | 输入端拼通道(Depth+IR 4ch) | 硬对齐(同相机同时刻) | ✅ 主力 |
| 特征级 | 双流网络中间交互 | 配对数据、同分布特征 | ❌ 0.6114 < 决策级 |
| 决策级(晚) | logits/prob 加权 | 各模态独立达标 | ✅ 最终 0.73 |
| 门控/动态 | 按样本/类别调权重 | 需要 val 拟合 + 互补 | ❌ 过拟合(0.64) |

- **同质模态(main+thermal)** 错误重叠高、融合空间小 → 朴素平均最优;
- **异质模态(视觉+惯性/骨架)** 理论互补,但弱模态质量不够时照样拖累;
- **铁律:模态的价值 = 信息独立性 × 单模态质量,两者缺一不可。**

---

## 4.14 集成方法论:logits 平均 / prob 平均 / SWA / seed

- **logits 平均**:不同模型 logits 尺度不同,嗓门大的主导——不稳;
- **prob 平均(我们最终用)**:softmax 后统一概率尺度,稳;`--prob_avg` 就是干这个的;
- **SWA(权重平均)失败的真实原因**:把 3 个在不同数据上收敛的模型做权重平均 = 把三个不同峰值的分布山平均成一片平原,决策边界模糊 → 测试预测塌缩到 26 类(LB 0.39)。**铁律:多折集成只用"每折独立推理 + logits/prob 平均",绝不用权重平均。**
- **oracle 分析**:每样本选最佳模态的完美融合 = 融合的理论上限,先算它再决定投不投。

---

## 4.15 测试时增强 TTA(flip / time)

- **Flip TTA**:推理时原图 + 水平翻转各跑一次、输出平均——零成本压方差(翻转在动作识别里近似合法,部分动作镜像等价)。
- **Time TTA(我们踩过的坑)**:想用多个时间窗口平均,但实现用了**连续 16 帧窗口**(10fps 只有 1.6s 局部快照),丢了全 clip 的时间多样性,直接把 0.73 拖到 0.65。**视频模型不能丢全局视角;时间 TTA 若要有效,窗口必须段内均匀/带偏移覆盖全程。**

---

## 4.16 模型量化 101(100MB 约束的核心数学)

- **对称 per-channel 量化**:每输出通道一个 scale,`q = round(w/scale)` ∈ [-2^(b-1), 2^(b-1)-1],反量化 `w ≈ q·scale`。
- **bit-packing(int<8)**:把每个值按位拆开压进字节流(int5 = 5bit/参数),`_pack_bits`/`_unpack_bits` 用位运算实现。
- **只量化"大权重张量"**:bias/BN/小张量保持 fp32(对精度敏感、占比小)。
- **int4 崩溃**:量化步长太大,碾平类间 logits 差异 → 分类边界瓦解(LB 0.71)。**R2Plus1D 提交级最低 int5。**
- 预算策略:在"崩之前"取最大压缩,把省下的 20MB 用来多放一个独立视角模型。

---

## 4.17 损失函数工程(CE / label smoothing / ArcFace / MPJPE)

- **CE**:默认,配合 label smoothing(4.5)使用。
- **ArcFace/Center Loss**:人脸/ReID 的"跨身份"利器(类内紧凑 + 类间分离),我们为 cross-subject 专门试——进行中,2891 样本量是个疑点。
- **MPJPE(辅助位姿回归头,auxpose)**:想用骨架几何监督视频网络——实测是**负向正则**(骨架本身有噪声、MPJPE 收敛不到 0,分散分类注意力)。**教训:辅助损失的质量配不上主任务,就别乱加。**

---

## 4.18 长尾/类偏置修正(v3 bounded-prior)

- 40 类长尾 29.5 倍,模型天然对高频类有偏置(soft-count 不平衡会 >2)。
- **bounded-prior**:朝均匀先验对 logit 做一次带阻尼的调整,只翻转**低置信度**的 clip,并设最大翻转比例(6%)兜底——推理侧零训练成本;先量"soft-count imbalance ≥ 2"才值得试。
- 反面:公开更新版用 damped-Sinkhorn 平衡丢 LB,提醒我们"越复杂的修正越容易过拟合测试噪声"。

---

## 4.19 小数据深度学习的完整策略(总纲)

> **预训练 > 增强 > 正则 > 模型结构** —— 遇到小数据任务,优先按这个顺序找增益:

1. **预训练迁移**(IG-65M / MotionBERT)是小数据的第一桶金(+10%~+17%);
2. **数据增强**是对抗过拟合的免费正则(+4.7pt);
3. **正则化与校准**(label smoothing、早停、dropout)是锦上添花;
4. **模型结构**的边际收益最小,且最容易误判(容量/超参/表示问题要先排查);
5. **数据量**(全量 +45%、外部同域数据)是大杠杆,但要先确认数据质量与同域性。

# 第五部分:面试高频问题与回答要点

> 每个问题给"作答骨架"。核心原则:**讲结果前先讲假设和过程,讲失败前先讲根因和判断依据**——面试官想听的从来不是"我拿了 0.73",而是"你怎么做到的、遇到坑怎么爬起来、以及你怎么判断一个方向值不值得投入"。

## A. 项目整体

**A1. 请用两分钟介绍你这个项目。**
> 一句话:在 RGB-Free(无彩色摄像头)、模型 ≤100MB、测试全是陌生人的三重约束下,用深度/红外/热像/3D骨架/IMU/雷达六种传感器做 40 类日常动作识别,最终 Leaderboard 0.73。
> 结构:任务三要素 → 数据物理事实(为什么 Depth+IR 能拼、Thermal 要单独)→ 技术栈(检测定位 + R2+1D 预训练 + 量化 + 决策级融合)→ 结果与关键教训。

**A2. 为什么不用 RGB?RGB 不是信息最全吗?**
> 任务明确 RGB-Free(隐私场景,测试不提供)。这决定了我们必须在"深度几何、红外剪影、热辐射、惯性"里找动作信息,也逼我们想清楚各模态的物理语义和对齐关系。

**A3. 你这个项目的"创新点"在哪?模型层面好像没有新结构。**
> 诚实回答:模型都是成熟组件(R2+1D/YOLO/MotionBERT),**创新在方法论和实验工程**——① 从硬件拓扑推导模态对齐策略;② 固定窗口裁剪保运动(不逐帧);③ 跨被试评估协议和防泄漏;④ "单模态达标→验证互补→再集成"的决策流程;⑤ 100MB 约束下的量化与预算重排。**深度学习竞赛的价值通常是"系统性地做对工程决策",不是发明新算子。**

## B. 方法与选择

**B1. 为什么选 R(2+1)D 而不是 TSM 或 3D CNN?**
> 消融说话:TSM-ResNet18(基线 E0)0.3615 → R2+1D-18 0.4618(+10%)。理由:分解卷积(先空间后时间)参数更省、引入中间 ReLU、优化更好。

**B2. 为什么 Depth_Color 和 IR 能拼成 4 ch?Thermal 为什么不行?**
> 硬件拓扑:Depth/IR/Skeleton 来自同一台 NYX 650(帧号天然对齐)→ 可早融合;Thermal 是独立相机、独立视场/帧率 → 只能单独建模 + 晚融合。**对齐是融合的前提。**

**B3. 为什么要 YOLO?裁剪时为什么用固定窗口而不是逐帧裁剪?**
> 检测负责"人在哪"(IR 剪影最清晰、99% 检测率);识别负责"在做什么"。固定窗口保住位移运动——逐帧裁剪会把"人从左走到右"这个核心线索抹掉。

**B4. 模型 ≤100MB 怎么处理的?**
> per-channel 量化 + bit-packing(int5),只量化大权重、bias/BN 保持 fp32;main int5(40MB)+ thermal int5(40MB)= 80MB。int4 会崩(量化误差碾平类间差异),所以提交级最低 int5。

**B5. 三个模态怎么融合的?为什么最终是朴素概率平均?**
> 决策级概率平均 + 翻转 TTA。因为 oracle 分析显示(即使完美选择也最多 ~0.7)融合空间小、两模态错误高度重叠,任何"学参数"的融合都在小 val 上过拟合(0.64 < 0.73)。

**B6. 类不平衡(长尾 29.5)怎么处理?**
> WeightedRandomSampler 类平衡采样 + label smoothing 校准 + (推理侧)v3 bounded-prior 类偏置修正兜底。

## C. 失败与复盘(面试最看重)

**C1. 你最大的失败是什么?**
> 推荐讲 Wave 1:随机划分本地 val 54% 沾沾自喜,提交 LB 32.8%——根因是身份/房间泄漏,然后重建 subject-split 协议。**转折点:从此所有结论都建立在"不撒谎的尺子"上。**

**C2. SWA 为什么会让预测塌缩?**
> 多折模型在不同数据上收敛到不同决策边界,权重平均 = 把不同的"山"平均成"平原"→ 边界模糊 → 测试预测塌缩到少数类(LB 0.39→0.62 修复)。铁律:只用 logits/prob 平均。

**C3. R2+1D-34 第一次训练为什么反而变差?**
> 误判成"容量过大"。真正根因是 lr=1e-3 太大,把 IG-65M 预训练权重冲垮(63M 预训练模型微调要用 1e-4)。修后 0.4252→0.5988。**教训:大模型+预训练要用小 lr;先排查超参再下架构结论。**

**C4. 为什么你们试了那么多方法都失败了?**
> 因为这些方法各自有文献背书但忽视了三个前提:① 小样本(2891)撑不起学参数的融合/对比;② 弱模态质量不够;③ fold 结论≠全量。**"关闭"本身是系统排除法的产物,不是没做。**

**C5. 怎么发现骨架跨折状态泄漏的?**
> fold1/fold2 的 val 高到不真实(0.91/0.98),折间方差巨大 = 泄漏信号。根因:模型在 fold 循环外创建被复用。修复:每折重建。**诊断信号(折间方差巨大)比代码审查更快。**

## D. 工程与实验管理

**D1. 你怎么保证实验结论可信?**
> subject-split 防泄漏断言、fold0 判据、不烧 LB、保底不动、每实验一行判据、结果归因到单一旋钮。

**D2. 用什么评估/验证协议?为什么?**
> 3 折 subject-CV(每折 6 个被试验证),对齐"测试全为陌生人"的真实分布;早期用随机划分吃了亏。

**D3. 时间 TTA 为什么会失败?**
> 用连续 16 帧窗口(10fps 仅 1.6s)丢失全 clip 时间多样性,视频模型不能丢全局视角。0.73→0.65,已回退。

**D4. 你们怎么分工处理"本地 vs 服务器"?**
> 本地只放样例 + 代码,全量在 GPU 服务器(SLURM);脚本参数化("数据路径 + 开关");上传前转 LF;A100 锁资源。

## E. 延伸/深挖(加分题)

**E1. 如果把骨架从 0.45 提到 0.6,融合能不能涨?**
> 理论会增加融合空间,但前提是与 main 的错误互补(骨架原生 3D 与视觉是不同视角,理论上互补)。我会先做 oracle/rescue 分析验证互补性,再决定投入。

**E2. 100MB 预算如果给你,你会怎么分配?**
> 用"预算重排"思维:在 int5 精度线之上,尽可能放进**信息独立性高**的模态(main + thermal 已被证明值;再有余量才考虑第二个 main seed 或骨架)。

**E3. 如果数据量翻倍,你会先做什么?**
> 先做反事实:翻的是"同域/同被试" vs "更多被试"。前者我会直接 re-run 全量 + 保留多 seed;后者我会重点验证 cross-subject 泛化(更有价值),并保留"弱模态可能转正"的可能性。

**E4. 你怎么判断一个方向值不值得投入?(决策框架)**
> ① 上限(oracle/论文基线)有多高;② 成本(fold0 快速对照 vs 全量);③ 风险(会不会烧掉稀缺的 LB/算力);④ 是否与现有强项互补。不满足就关闭。

## 6.2 第一句话:「多模态异构数据建模与融合」逐词深挖

**简历原文**:在模型≤100MB 约束下,对 Depth/IR/Thermal/Skeleton/IMU/mmWave 六模态按物理特性分路建模,视频主干(R(2+1)D / TSM 时序移位)与骨架图卷积(ST-GCN joint+bone 双流)异构编码,设计 late fusion 融合策略,实现多源传感器协同动作识别。

**逐词应该怎么讲(对应真实方法与文件)**:

- **"按物理特性分路建模"** → 这是你最该重点展开的**设计哲学**。讲纯的硬件拓扑:**Depth_Color + IR + Skeleton 来自同一台 NYX 650(帧号天然对齐)→ 可以早融合拼 4ch;Thermal 是独立相机(独立视场/帧率)→ 只能单独建模、最后晚融合;Skeleton 是 3D 米制坐标(不是像素)→ 只能独立建模,不能拿去裁图**。一句话:**"融合策略不是拍脑袋定的,是从传感器硬件拓扑推导出来的"**。→ 对应 `M10 / M24`,README 里 1.3 节。

- **"视频主干 R(2+1)D/TSM + 骨架图卷积异构编码"** → 讲清楚你其实造了两类异构编码器:
  - 视频流:`R(2+1)D-34 + IG-65M`(分解卷积,先空间后时间,参数更省、优化更好),TSM 是起点基线 → `M2/M4/M14`;stem 改成 4ch 输入(Depth+IR)。
  - 骨架流:从 `ST-GCN(joint+bone)` 演进到 `MotionBERT(DSTformer 自注意力)` → `M19/M20`;**两类编码器一个吃像素流、一个吃拓扑流,本身就体现"异构"**。

- **"设计 late fusion 融合策略"** → 升级你的表述:你**不是只做了一个融合**,而是**做了全套对比后选了决策级**:
  - 早融合(Depth+IR 4ch,✅ 主力)→ 特征级(dual_fusion 0.6114 ❌)→ 决策级(prob 平均,✅ 最终 0.73)。
  - 关键方法论:**先用 oracle/互补性分析算清"融合天花板"**(rescue/oracle≈0.68-0.71,接近 main 本身)→ **得到"融合空间很小、别硬融合"的结论** → 于是选择最朴素也最稳的概率平均 → `M26/M25`。

**这条句话的杀手追问(先想好答案)**:

- Q1: **六模态为什么不全用?IMU、mmWave 是不是浪费了?**
  → "分档"回答:论文基线 IMU 45%/mmWave 46%(随机划分下都是最弱),我们实测 IMU 0.35(1D-CNN),天花板不足;且票价是一码事,关键是**模态的价值 = 信息独立性 × 单模态质量**,IMU/Radar 和 Depth+IR 相比既弱又没进互补区。**全部数据保留,随时可回炉**(`M32/M10.2`)。
- Q2: **为什么 Depth+IR 能拼 4ch,而 Thermal 不能?**
  → 硬件对齐:同相机同帧号才算对齐,才配早融合;Thermal 是独立相机,只能"稳定解析",晚融合(见 6.2 第一段)。
- Q3: **ST-GCN 边集为什么不能用 COCO?** → H3.6M-17 和 COCO-17 关节顺序/派生点/连接都不同,直接用会信息错乱(`M19`+名词表 G)。
- Q4: **joint 流和 bone 流区别?** → joint=关节坐标;bone=骨骼向量(相邻关节差),两者是互补表示(位置 vs 方向),双流可以涨点,但最终不如预训练。
- Q5: **为什么最后是"概率平均"而不是"logits 平均"或加权?** → 概率平均对"不同模型 logits 尺度不一致"稳健;学参数的加权在 2891 样本上过拟合(类感知 0.64 < 0.73)(`M25/M27`)。
- Q6: **100MB 约束怎么破?** → per-channel 量化 + int5 bit-packing,只量化大权重、bias/BN 保 fp32,main(40MB)+thermal(40MB)=80MB;**int4 会崩(量化误差碾平类间差异),提交级最低 int5**(`M21-M23`)。

## 6.3 第二句话:「人体检测与时序建模」逐词深挖

**简历原文**:基于 YOLO11 在红外图上做人体检测,多帧探测融合生成固定裁剪窗口以保留运动线索;结合 TSM 时序移位与 3D 卷积建模动作时序动态,提升视频理解能力。

**逐词应该怎么讲**:

- **"红外图 + YOLO11 检测"** → 为什么在 IR:主动红外的人体剪影对比度最高、受环境干扰最小,检测率 99%(训练)/97.5%(测试);X11n 轻量,离线缓存 bbox(`M6`)。
- **"多帧探测融合生成固定裁剪窗口"** → 这是你最值钱的一句话线,要展开成三段式:
  1. **8 帧均匀探测**(不是逐帧)→ union 并集 → 1.4x 放大 → 正方形 → **全程一个固定窗口**;
  2. **为什么固定而逐帧**:逐帧贴人会把"人在画面里移动"的位移抹平,固定窗口让网络在固定坐标系里看运动;
  3. **消融背书**:+固定裁剪 = +4pt(0.46→0.50)(`M7`)。
- **"TSM 时序移位 + 3D 卷积建模时序"** → 按 6.1 第 3 条修正讲:TSM 是基线/探路,主线是 3D 分解卷积 R(2+1)D;16 帧 endpoint-uniform 采样保住全局时间结构(32 帧反而失败,clip 平均只有 ~29 帧)(`M2/M4/M5`)。

**杀手追问**:

- Q1: **检测错了/找不到人怎么办?**
  → 检测不到就退回"整帧当窗口"(归一化 0/1 全帧),训练/推理都能兜底不崩;公开方案还有把 IR 探测失败换 Depth_Color 重测的 fallback,我们同样保留。
- Q2: **固定窗口会不会把人裁掉一部分?** → margin=1.4x + 最小边长 35% 兜底,宁可留白不可切肢体。
- Q3: **帧数/帧率怎么定?** → 16 帧是"够覆盖结构 + 不注水"的甜点;clip 平均 Depth/IR 仅 29 帧,32 帧靠重复帧注水反而降点(0.33)。
- Q4: **R(2+1)D 为什么比 TSM 强 10 个点?** → 分解卷积(先空间后时间)+ 中间 ReLU = 参数更省、优化更好、自带正则(`M4`)。

## 6.4 第三句话:「跨被试泛化与实验方法」逐词深挖

**简历原文**:采用 subject-CV 划分规避身份/环境捷径,引入置信度掩码、尺度归一化等数据增强提升跨被试鲁棒性;搭建消融实验框架隔离验证检测、时序、采样各模块增益,以数据实测驱动方法迭代。

**逐词应该怎么讲**:

- **"subject-CV 规避身份/环境捷径"** → 讲 Wave 1 的真实事故:随机划分本地 val 54.3%,提交 LB 只有 32.8%——**21.5 个点是身份/房间泄漏**;重建"按被试分组 + 防泄漏断言"的 3 折 subject-CV 后,一切结论才可信(`M8`)。
- **"置信度掩码、尺度归一化等数据增强"** → **这里是唯一必须"修正表述"的地方**:
  - ✅ **尺度归一化**:骨架做"中心化(减骨盆)+ 肩宽/torso 归一化"去身份/体格差异(`M18`);
  - ✅ **真正的增强**:翻转/亮度/对比度/缩放/平移(aug2)+ 骨架 random_moving(`M11`)、类平衡(`M9`)、label smoothing(`M12`);
  - ❌ **"置信度掩码"**:如 6.1 所述——实测 conf 恒 1.0 后被**删除了**,这是"数据实测驱动"的正面例子,别当成"用着"的方法讲。
- **"搭建消融实验框架隔离验证检测/时序/采样各模块增益"** → 亮出你的**消融表**(这几乎是 HR 最爱的"系统性"证据):
  | 模块 | 消融 | val | 结论 |
  |---|---|---|---|
  | 主干 | TSM→R2+1D-18 | 0.36→0.46 | 分解卷积更强 |
  | 检测 | +YOLO 固定裁剪 | 0.46→0.50 | 定位有效 |
  | 采样 | 16→32 帧 | 0.35→0.33 | 帧数要贴任务 |
  | 增强 | aug0→aug2 | +4.7pt | 增强是真正则 |
  | 预训练 | IG-65M + lr 1e-4 | 0.43→0.60 | 微调配方关键 |
  | 量化 | int5 vs int4 | 0.73 vs 0.71 | int4 崩,下限 int5 |
- **"以数据实测驱动方法迭代"** → 攒 3 个"实测打脸"故事(面试杀手锏):
  1. conf 恒 1.0 → 删通道;
  2. 归一化域 bug(ImageNet→Kinetics)让 Thermal +5pt;
  3. SWA 权重平均 → 预测塌缩 LB 0.39,改 prob 平均 → 0.62。

**杀手追问**:

- Q1: **你怎么量化"检测 vs 时序 vs 采样"各自的贡献?** → 就是上面那张消融表——**每次只改一个变量,其余锁死**,数字说话。
- Q2: **增强会不会增强过头破坏物理语义?** → aug3 收益饱和 + "保护伪彩色几何语义"(亮度/对比度可动,距离-颜色映射不能乱)(`M11 ④`)。
- Q3: **你怎么确认跨被试数字真/假?** → ① subject 级划分 + 断言;② 折间方差巨大=泄漏信号 √;③ fold 与全量交叉验证(如 aug1 fold0 最优但全量崩)。
- Q4: **"实测驱动"最典型的例子?** → 首选讲 SWA(用了结果崩→定位根因→改集成方式 0.39→0.62)。

## 6.6 用简历版本讲"两分钟版"故事(背诵用)

> "这是一个**没有 RGB、测试全是陌生人、模型不能超 100MB** 的 40 类动作识别竞赛。我先从传感器硬件拓扑推导出融合策略——深度+红外同相机所以拼 4ch 早融合,热像是独立相机所以单独建模、最后决策级融合,骨架是 3D 米制坐标所以独立建模。主线用 YOLO11 在红外上做固定窗口裁剪保运动、R(2+1)D-34(IG-65M)做主干的 4ch 视频模型;骨架走 MotionBERT 预训练。关键教训是早期随机划分被我发现有 21.5 个点的泄漏,重建 subject-CV 之后的所有结论才可信。通过一轮消融(主干/裁剪/增强/量化/集成)把 val 从 0.36 推到 0.60,再用全量 18 被试 + 双 seed 推到 LB 0.711,最后加一个**独立视角**的热像模型做概率平均,到 **LB 0.73**。整个过程的纪律是:新方法一律先在 fold0 对照、超过基线才升级,不烧正式提交——所以那些'花哨方法'(对比学习、门控融合、伪标签)都用最低成本验证后体面地关闭了。"

## 结尾:三个词记住整个项目

> **运动优先** —— 动作是时间模式,时序建模是一等公民,固定窗口保位移;
> **检测定位** —— 检测只管"人在哪",识别只管"在做什么",两者解耦;
> **单模态达标再集成** —— 每个模态先独立做到最好,验证互补再融合,否则就是拖累。

从 32.8% 的错误开始,到 0.73 的最终成绩——真正让你能把它讲成"自己的项目"的,不是任何一行代码,而是**这几条用失败换来的方法论和判断纪律**。
